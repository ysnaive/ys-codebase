> 主題：`task-cache` 雜湊感知之跨語言增量建置與測試編排基座  
> 歸檔日期：2026-11-02

## 1. 背景與長期願景 (Background & Vision)

- **核心痛點與動機**：
  - **跨語言專案建置與測試指令碎片化且缺乏統一快取帳本**：母倉多模組沙盒測試與下游多語言專案（如 C# / C++ 混合建置）各自維護異質工具鏈指令，普遍缺乏跨次執行的輸入指紋快取帳本、統一的 `include/exclude` 空間抽象，以及常駐背景熱機監聽。
  - **無關變更重複觸發全量重跑與冗長日誌洗版**：當開發或工作流推進僅修改局部模組或純文檔時，傳統流程仍頻繁啟動未受影響模組的測試沙盒或外部編譯器；且外部編譯器與測試框架常輸出數千行終端機日誌，嚴重消耗 AI 上下文視窗。
  - **測試驗收與歸檔守門缺乏機器可驗證之防偽印章**：工作流在測試驗收與計畫歸檔時，缺乏自動核對「當前原始碼樹指紋是否與最後一次測試通過狀態一致」的機制，無法從底層機械攔截「修改最後一行程式碼後未重跑測試即宣告通過」的漏洞。
- **長期願景與目標定位**：
  - 遵循 **「外部執行工具鏈 + `include/exclude` 空間抽象 + `server` 背景熱機監聽 + `callback` 生命週期管線 + `agents-workflow` 技能與守門注入」** 之套接強化設計，打造 **`task-cache`** 模組。
  - 實現 **「對上統一 AI 動作抽象（`task status / run`）、對下各自綁定最小重跑單元（DAG）」** 的跨語言增量建置與測試編排基座，同時提供毫秒級快取命中跳過、終端報錯降噪膠囊（Error Capsule）與防偽造測試印章（Verification Stamp）。
- **範疇與邊界約束**：
  - **拒絕薄指令轉發（No Thin Wrappers）**：不作純命令列別名轉發，核心價值聚焦於輸入雜湊帳本、空間過濾、背景指紋預熱、報錯降噪與跨模組驗收印章。
  - **粗粒度快取跳過與原生增量編譯分工**：`task-cache` 專責「模組級 / 專案級 / 測試套件級」的輸入指紋快取跳過與驗收蓋章；當指紋變更需實際執行編譯時，仍交由底層原生編譯器（如 `dotnet`、`cmake`）發揮其物件檔級別的細粒度增量編譯能力。

## 2. 抽象架構原則與核心設計概念 (Architectural Principles & Concepts)

- **核心設計不變量 (Core Invariants)**：
  1. **「對上統一抽象、對下各自綁定」雙層架構**：
     - **上層（AI 與工作流統一介面）**：無論身處何種語言專案，AI Agent 與開發者永遠呼叫統一的 `task status`、`task run build`、`task run test` 標準語意。
     - **下層（專案最小重跑單元 DAG 綁定）**：透過 `include/exclude` 與 `depends_on` 定義任務節點拓撲（例如母倉拆分獨立模組測試節點並依模組依賴串接；下游專案綁定核心庫編譯與測試節點）。當僅修改特定模組、測試檔或純文檔時，未受影響的任務節點因輸入指紋未變直接命中快取跳過。
  2. **複合任務輸入指紋（Composite Task Fingerprint）**：任務指紋除了計算 `include/exclude` 範圍內的檔案內容雜湊外，必須一併納入「任務指令字串本身、上游依賴任務指紋（`depends_on`）與關鍵環境/組態設定（如語言執行期版本或編譯參數）」，避免變更編譯參數卻誤中舊快取；同時支援 `--force`（或 `--no-cache`）強制穿透重跑以應對非確定性測試或外部環境異動。
  3. **防偽造測試印章（Verification Stamp）**：透過任務成功的 `callback` 生命週期管線，每次測試綠燈時自動將當下程式碼樹與任務指紋蓋章記錄；當執行 `plan verify` 或 `plan archive` 準備結案時，系統直接核對「當前原始碼指紋是否與最後一次測試通過印章一致」，若修改程式碼後未重跑測試則由守門員直接攔截。
- **概念機制與互動協議 (Conceptual Mechanism)**：
  - **`server` 後台預熱指紋（零延遲狀態感知）**：掛載於 `server` 後台監聽檔案變更事件，在檔案存檔瞬間於背景增量更新受影響任務節點的指紋狀態，使前台執行 `task status` 或 `task run` 時轉為純記憶體查表，免除每次重新掃描磁碟計算雜湊的延遲。
  - **終端機報錯降噪膠囊（Error Capsule）**：將外部編譯器或測試框架的完整輸出落地存檔至快取空間，前台僅擷取關鍵錯誤行、失敗斷言與日誌檔案指針回傳給 AI，大幅降低 Token 消耗與解析失誤率。
  - **`agents-workflow` 驗收與歸檔守門協同**：與 `/auto`、`P06` 測試驗收及 `plan verify / archive` 對接，提供確定性的測試狀態查驗與防偽印章校驗。

## 3. 解鎖條件與演進構想 (Unlock Criteria & Evolution Stages)

- **前置解鎖條件與觸發時機**：
  - 當母倉多模組回歸測試耗時增長，或下游多語言專案需統一接入 AI 自動化建置測試與防偽驗收守門時，即可啟動立項。
- **階段演進構想 (High-Level Stages)**：
  - **Stage 1（核心快取帳本、DAG 編排與 Error Capsule）**：建立任務節點組態 Schema（`include/exclude`、`depends_on`、指令與環境指紋）、本地快取帳本、終端機報錯降噪膠囊與 `--force` 強制穿透機制。
  - **Stage 2（`server` 背景指紋預熱連動）**：對接常駐 `server` 檔案變更監聽管線，實現存檔即時更新任務指紋與零延遲 `task status / run` 查表。
  - **Stage 3（`agents-workflow` 防偽測試印章守門）**：透過成功 `callback` 簽發測試通過印章，並與 `plan verify` / `plan archive` 結案守門整合，強制校驗原始碼指紋與最新測試印章一致性。
