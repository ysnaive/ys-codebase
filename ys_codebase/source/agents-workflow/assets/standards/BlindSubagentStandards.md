## 4. [!] 盲眼認知隔離與去錨定轉譯協定

當任務目標為**消除主代理 Confirmation Bias 與 Recency Anchoring**（包含無假設探索、冷眼靜態盲審、跨輪收斂盲測與 Devil's Advocate 反向查驗）時，在完全遵守上方 `§1 ~ §3` 物理與通訊圍欄的基礎上，**強制疊加以下盲眼認知隔離協定**：

### 4.1 主代理派發前之去錨定提示詞淨化
主代理在盲眼模式下的核心角色為**去錨定轉譯器**，派發 Prompt 前強制執行三項淨化：
1. **剝除主視窗假設與失敗嘗試**：**嚴禁**在派發 Prompt 中透露主視窗當前的猜測結論、先前失敗的嘗試方向或主觀傾向的方案。
2. **零劇透 `Pointer-Only` 傳址**：派發實作後審查或跨輪盲審時，**嚴禁預先條列、摘要或劇透本次已修改之檔案清單、新增項目或變更細節**；僅提供目標範圍路徑與驗收基準，由盲眼 Subagent 自行透過工作區狀態或第一手資料檢索獨立發現。
3. **誘導性是非題轉譯為開放式中立命題**：
   - ❌ **誘導性提問（禁止）**：「請幫我檢查某處是不是因為 X 原因才導致異常？」
   - ✅ **去錨定中立命題（強制）**：「請針對某目標範圍在特定條件下發生之客觀現象（附客觀輸入與觀測現象），獨立追蹤第一手資料並定位所有潛在成因與證據座標。」

### 4.2 前置脈絡黑盒隔離與第一手事實取證
依盲眼任務性質，嚴格管制 Subagent 可讀取的前置脈絡與歷史紀錄範圍：
1. **無假設盲眼探索與跨輪零錨定盲審**：
   - **完全黑盒禁讀歷史過程與前輪報告**：嚴格禁止盲眼 Subagent 讀取主視窗之歷史討論紀錄、過程日誌或前輪診斷報告，強制以 **100% 全新視角直接檢視當前工作區第一手目標資產（如原始文件、數據或源碼）**，根除前輪結論錨定。
2. **基準對齊冷眼靜態盲審**：
   - **僅讀客觀契約與驗收標準、不聽過程劇透**：允許 Subagent 根據主代理給定的基準路徑，自行讀取需求契約或品質標準，並自行搭配版本控制狀態（如 `git status --short` 與 `git diff HEAD`）逐一核對實作變更與新建之 **`Untracked (??)` 檔案**（對新建未追蹤檔案必須直接以唯讀工具檢視全文，杜絕漏審）。

### 4.3 誠實收斂判定與防吹毛求疵鐵律
為杜絕盲眼 Subagent「為了證明自己有工作而硬湊問題（Finding-by-Force）」之反模式，派發時必須明確賦予以下誠實收斂契約：
1. **僅回報違反客觀基準之實質缺失**：
   - 僅允許回報違反明確規範、規格契約遺漏、邏輯破綻、淺層敷衍修補或實質品質硬傷之具體證據座標。
   - **嚴禁回報無關緊要的主觀偏好、個人命名習慣或表面排版微調**。
2. **零硬傷誠實放行（`REVIEW_STATUS: PASSED`）**：
   - 若經獨立核驗確認目標產物已完全符合基準契約、無實質硬傷，**強制直接回傳 `REVIEW_STATUS: PASSED`（或於收斂盲審中直接判定零問題結案）**，嚴禁為填滿表格而強行挑刺或拆解已收斂之高內聚結構。

### 4.4 Devil's Advocate 反向查驗協定
針對高風險決策或破壞性處置（如物理刪除疑似冗餘資產、合併近似結構、大規模拆分重組或淘汰候選方案），盲眼 Subagent 扮演 **Devil's Advocate（反方辯護人）**執行反向證偽：
1. **反向尋找反證與隱性依賴**：不預設主視窗提案正確，而是主動結合調用／引用圖譜與全倉檢索，全力尋找該目標是否仍存在隱性跨處引用、間接契約綁定或特殊外部依賴；只要找到任一合法引用或破壞性反證，即攔截該處置。
2. **差異邊界不變量核對**：逐一比對擬合併、簡化或拆解項目間的局部差異與邊界條件不變量（如特殊錯誤語意、狀態同步邊界或關鍵限定條件），逐條回報 `[VERIFIED_SAFE]` 或 `[REJECTED: 附反證座標]`，防止誤傷既有核心語意。

## 5. 四大盲眼任務原型與專用派發訊息模板

### 5.1 四大盲眼任務原型速查矩陣

| 原型代號與名稱 | 適用場景 | 前置脈絡與歷史紀錄權限 | 回傳模式與收斂判準 |
| :--- | :--- | :---: | :--- |
| **原型 ①：無假設盲眼探索與根因排查** | 未知跨範疇摸底、多主題獨立調研，或同一問題連續試錯卡關需切斷主視窗先入為主偏見 | **完全禁讀歷史過程與前輪結論** | `Mode I`（150~300 Tokens 結構化發現與精確證據座標） |
| **原型 ②：基準對齊冷眼靜態審查** | 交付前品質審查、結案複審，或開發者要求對當前變更進行無偏見品質把關 | **僅讀驗收基準與規格契約**<br>*(禁主視窗劇透變更明細)* | `Mode I`（僅列實質硬傷座標；無硬傷直回 `REVIEW_STATUS: PASSED`） |
| **原型 ③：Devil's Advocate 反向事實查驗** | 動手執行高風險刪除、結構合併、物理拆分或重大取捨前之反向證偽把關 | **僅讀待查驗之提案條目** | `Mode I`（逐條標註 `[VERIFIED_SAFE]` 或 `[REJECTED: 附反證座標]`） |
| **原型 ④：分區隔離平行盲審／獨立執行** | 跨多個獨立範疇平行產出無偏見評估報告、或執行跨輪零錨定收斂盲測 | **跨輪盲審禁讀前輪報告**；<br>授權落檔指定目標路徑 | `Mode II`（直接落檔目標路徑 + 回傳 $< 50$ Tokens 收據；允判零問題收斂） |

### 5.2 主代理 $\to$ 盲眼 Subagent 專用派發訊息模板

派發盲眼 Subagent 時，以本模板取代 `§3.1` 通用模板，強制顯式注入「去錨定中立命題」、「黑盒禁讀邊界」與「誠實收斂／反向證偽判準」：

```markdown
【盲眼任務原型與中立命題】
- 盲眼原型：[原型 ① 無假設探索 | 原型 ② 冷眼靜態審查 | 原型 ③ Devil's Advocate 反向查驗 | 原型 ④ 分區平行盲審]
- 開放式命題：[僅陳述客觀觀測現象、待審目標或待證偽提案；0 主視窗猜測、0 誘導性是非題、0 已改檔案劇透]

【Pointer-Only 座標與黑盒隔離邊界】
- 探勘目標：[目標目錄 / 檔案路徑（若為審查，自行搭配 `git status --short` 與 `git diff HEAD` 檢視變更與 `Untracked (??)` 新檔）]
- 驗收基準：[允許讀取之規格契約或品質標準路徑；若為原型 ① 則填「無，直接從第一手資產取證」]
- 黑盒禁讀：[明確列出嚴禁讀取之歷史討論、過程日誌或前輪報告路徑]

【邊界圍欄與誠實收斂判準】
- 讀寫權限：[唯讀 (Single-Writer，嚴禁修改檔案或啟動實機建置/測試) | 原型 ④ 授權寫入：`<指定報告路徑>`]
- 收斂鐵律：僅回報違反客觀基準之實質硬傷與精確座標（嚴禁挑剔主觀偏好或表面排版）；若無實質硬傷強制直接回傳 `REVIEW_STATUS: PASSED`（或零問題收斂）；若為原型 ③ 則逐條尋求反證並標註 `[VERIFIED_SAFE]` 或 `[REJECTED: 附反證座標]`。

【回傳契約】
- 採用模式：[Mode I（150~400 Tokens 濃縮結論與證據座標） | Mode II（落檔指定路徑 + 回傳 < 50 Tokens 收據）]
```
