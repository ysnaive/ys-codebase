# 通用子代理調度、職責正交門檻與物理通訊標準

本文件定義調度 Subagent 時的「預設主代理 Inline 執行 vs. 跨範疇職責正交委派門檻」、物理安全圍欄、標準派發訊息模板與雙模回傳通訊契約（適用於調研、文檔、規劃、分析、審查與實作等各類任務）。

<!-- yscb:ignore:begin -->
> [!IMPORTANT]
> **單一版本明確引用原則（僅供技能與標準維護者查閱）**：  
> - **知情委派**：當 Subagent 可共享主視窗目標脈絡與既定規格以分擔獨立子任務時，技能內**僅引用本文件（`SubagentStandards.md`）**。  
> - **盲眼委派**：當需要切斷主視窗先入為主假設、Confirmation Bias 或既有結論以獨立取證／審查時，技能內請**直接改為引用 `BlindSubagentStandards.md`**（該文件前段已透過 `SUBAGENT_BASE_STANDARDS` 節點注入完整包含本文件所有規範，引用盲眼版本時嚴禁重複引用本標準版本）。

## 1. [!] 預設主代理 Inline 與職責正交啟動界線

為保護有限 Token 配額並避免 Subagent 冷啟動之 Context Preload 開銷，嚴禁無差別派發 Subagent，亦**嚴禁以硬編碼檔案數或行數常數作為機械式觸發門檻**，一律以**「是否橫跨多個獨立範疇（如多主題、多份文檔、多模組或多 Class）並產生職責正交」**作為評判界線：

| 結構影響範圍與職責正交性評判 | 預設執行主體 | 判定基準與工程原因 |
| :--- | :--- | :--- |
| **① 單一職責軸線／明確局部修復** | **主代理 Inline 執行** | 任務屬於明確之局部修復（如已知根因之單點 Bug 修復）或收斂於單一主題、單一文檔、單一模組／Class 群組之同一職責軸線內。由主代理直接在當前視窗內完成檢索、處理與自檢，達成 **0 Subagent 冷啟動開銷**。 |
| **② 全新功能或模組／跨範疇職責正交** | **委派 Subagent 執行** | 任務涉及**全新功能開發 (`Feature`)、新建模組／組件（非明確之局部 Bug 修復）**，或**橫跨多個互不干擾的獨立子範疇且具備職責正交性**（例如：多主題平行文獻／技術調研、跨多份文檔或規格之獨立撰寫與審校、跨多個模組或 Class 之正交變更、高過程噪音之廣域探索），或由開發者**顯式指定**時優先啟動。 |
| **③ 無 Subagent 環境自動降級** | **主代理 Inline 執行** | 若當前宿主執行環境不支援 Subagent 調度工具，無條件自動降級由主代理於主視窗內聯分段執行。 |

## 2. 物理調度與邊界安全四大圍欄

凡啟動任何 Subagent（含知情委派與盲眼委派），主代理與 Subagent 必須嚴格遵守以下四大物理圍欄：

1. **單回合平行派發上限（3~4 Subagents / Turn）**：
   - 當平行子任務數量超過 4 個時，主代理在單一對話 Turn 內同時呼叫 Subagent 工具的數量**上限為 3~4 個**（須分 2 個以上 Turn 分批派發）。
<!-- yscb:ignore:begin -->
   - **技術原因**：單回合同時序列化過多長篇 Subagent 呼叫，極易觸發底層模型單次 Output Token 截斷與呼叫參數閉合崩潰。
<!-- yscb:ignore:end -->
2. **`Pointer-Only` 純指針傳址原則**：
   - 主代理派發 Subagent 時，傳入之 Prompt **必須採 `Pointer-Only` 極簡傳址**（僅給定任務目標、責任邊界、目標檔案／資源路徑指針與需遵循之規範手冊連結）。
   - **嚴禁在派發 Prompt 參數中直接複製貼上長篇原文、完整文件或大段原始碼**，交由 Subagent 進入獨立視窗後自行以檢索與區段讀檔工具按需載入。
3. **讀寫權限圍欄與共用資源互斥**：
   - **唯讀型 Subagent（調研／分析／排查／審查）**：嚴守 `Single-Writer` 鐵律，**嚴禁新增、修改或刪除工作區任何檔案**，且**嚴禁在唯讀 Subagent 內啟動具狀態副作用或耗時的全域程序**。
   - **寫入型 Subagent（分區撰寫／分區實作）**：各平行 Subagent 僅允許修改自身被授權之專屬檔案或子目錄範圍（平行 Subagent 間之寫入範圍必須正交不重疊）；平行執行期間**嚴禁各自觸發全系統建置、全域驗證或環境變更操作**（避免併發爭搶共用鎖或破壞工作區狀態），一律待 Subagent 全數回傳後由主代理統一執行。
4. **單層星型拓撲與連續受阻二振熔斷**：
   - **禁止遞迴派發**：Subagent 調度嚴守「主代理 $\to$ Subagent」單層星型拓撲，Subagent 內部不得再次派發下一層 Subagent。
   - **二振熔斷**：Subagent 於執行中遭遇同一阻礙**連續 2 次無法解決**，或發現需跨出授權邊界修改外部未授權範圍時，必須立即停手並將現場座標回報主代理裁決。

## 3. 標準派發訊息模板與雙模回傳契約

由於 Subagent 啟動時為全新的空白視窗（`0 Context`），主代理派發任務時必須使用結構化訊息明確注入邊界與回傳格式，並強制節流回傳內容：

### 3.1 主代理 $\to$ Subagent 標準派發訊息模板

```markdown
【任務目標與職責】
- 角色定位：[例：子系統實作代理 / 專題文獻調研代理]
- 核心任務：[1~2 句話明確定義待解決問題或交付成果]

【Pointer-Only 範圍與輸入座標】
- 目標路徑：[負責之目錄 / 檔案路徑 / 檢索關鍵字]
- 參考基準：[需按需讀取之規格、標準或技能手冊路徑]

【邊界與安全圍欄】
- 讀寫權限：[唯讀 (Single-Writer，嚴禁修改任何檔案或執行耗時全域程序) | 授權寫入：<限定檔案/子目錄路徑>，嚴禁觸碰範圍外檔案或執行全域建置/測試]
- 異常熔斷：遭遇同一阻礙連續 2 次失敗或需跨出授權邊界時，立即停手回報現場座標。

【回傳契約】
- 採用模式：[Mode I：不落檔，回傳 150~400 Tokens 結構化摘要（① 核心結論 ② 精確證據座標 `路徑:行號/章節` ③ 影響與建議） | Mode II：直接寫入 `<目標路徑>`，僅回傳 < 50 Tokens 驗收收據（若涉及外部待連動變更，附帶 `[Cross-Boundary Handoff]` 清單）]
```

### 3.2 Subagent $\to$ 主代理 雙模回傳與跨邊界交接契約

1. **`Mode I` — 結構化濃縮摘要回傳（適用於調研、分析、排查或審查等不直接落檔之任務）**：
   - Subagent 不落檔，僅向主代理回傳 **150 ~ 400 Tokens 以內**之高密度結構化摘要：
     - ① **核心結論與發現**（關鍵論點、候選方案權衡、根因線索或審查結論）。
     - ② **精確證據座標**（`檔案路徑:起訖行號`、文檔章節標題或關鍵符號／條目名稱）。
     - ③ **影響範圍與後續建議**。
   - **嚴禁在回傳訊息中傾倒完整檔案原文、大段原始碼或長篇過程日誌**。
2. **`Mode II` — 授權直接落檔 ＋ 極簡收據回傳（適用於平行產出多份文檔／報告或分區修改之任務）**：
   - 當任務需產出較長篇幅成果或涵蓋多個獨立分區時，為避免壓縮摘要遺失細節或撐爆主代理視窗，**主代理可顯式授權各 Subagent 直接將成果寫入其專屬目標路徑**。
   - Subagent 完成落檔後，僅向主代理回傳 **$< 50$ Tokens 的極簡驗收收據**（包含：已落檔路徑、完成狀態與核心摘要）。
3. **跨邊界連動交接清單（`[Cross-Boundary Handoff]`）**：
   - 在平行分區修改模式下，若 Subagent 在授權範圍內的變更（如文檔術語更新、規格修訂或介面調整）需要同步連動**自身授權範圍以外**的外部檔案，Subagent 嚴禁越界修改，必須於回傳收據中附帶標準化交接清單：
     `[Cross-Boundary Handoff] 變更項目（舊定義 -> 新定義） | 外部受影響座標清單 (路徑:行號/章節)`
   - 由主代理在彙整所有 Subagent 回條後，一次性批次完成外部連動更新與整體檢驗。
