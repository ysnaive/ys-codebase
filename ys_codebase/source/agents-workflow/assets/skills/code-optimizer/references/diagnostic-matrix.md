## 1. 三級嚴重度判準 (Severity Tiers: P0 / P1 / P2)

診斷報告中所有發現之結構問題，強制按以下客觀標準分級（若某維度無異常，明確標記為 `Pass`，嚴禁無中生有湊數）：

- **`P0（高危破窗 / 架構腐化與資源隱患 — 強烈建議優先修復）`**：
  - 模組間循環依賴（Cyclic Dependency）、跨模組直接篡改私有狀態、靜默吞噬例外（Silent Catch）、外部資源（檔案/鎖/子進程）未在異常路徑確定性釋放、繞過專案核心安全或路徑抽象層、或超過 500~800 行且承載多重正交職責之巨型破窗檔案（God File / God Class）。
- **`P1（結構耦合 / 可維護性阻礙 — 標準重構目標）`**：
  - 頂層公開方法混雜宏觀業務編排與底層細節（違反 SLAP）、類別內大量方法未讀寫實例狀態卻與有狀態生命週期強綁定、跨方法重複出現同構控制流骨架、超過 3~4 層深層巢狀（Arrow Anti-pattern）、長參數列或以鬆散非結構化字典跨階段傳遞關鍵狀態、或無任何入向引用的孤兒死代碼（Dead Code）。
- **`P2（局部異味 / 可讀性打磨 — 順手收斂項目）`**：
  - 散落的魔術常數（Magic Literals）、可透過提取具名階段函式消除的段落分隔註解、或局部冗餘的中間變數與過時廢棄註解塊。

## 2. 跨語言五維度靜態診斷矩陣 (D1 ~ D5)

| 維度代號 | 診斷維度名稱 | 核心審查指標（跨語言通用軟工抽象） | 典型病徵與審查檢核點 | 對應重構策略 |
| :---: | :--- | :--- | :--- | :---: |
| **`D1`** | **職責內聚與抽象層級**<br>*(Cohesion & Abstraction Levels)* | • 單一職責原則 (SRP)<br>• 單一抽象層級原則 (SLAP)<br>• 有狀態實體与無狀態運算分離 | 1. **巨型類別/檔案 (God Class/File)**：單一檔案同時塞入資料模型定義、底層解析演算法與高階業務調度。<br>2. **抽象層級混雜**：公開入口函式內同時出現高階業務步驟與底層字串正規表達式切割、位元操作或 I/O 緩衝細節。<br>3. **假性實例方法**：類別中存在大量僅依賴傳入參數、完全不讀寫實例欄位（`self` / `this`）的純運算方法。 | `S1`, `S2`, `S6` |
| **`D2`** | **調用耦合與拓撲健康度**<br>*(Coupling & Topology Hygiene)* | • 入向/出向耦合度 (Ca / Ce)<br>• 無環依賴原則 (ADP)<br>• 最小可見性與死代碼清零 | 1. **雙向或環狀依賴**：模組 A 匯入模組 B，同時模組 B 又反向匯入模組 A。<br>2. **過度暴露 (Over-exposure)**：僅供內部使用的輔助函式被暴露為公開介面，或在 `Mode A` 下殘留多餘的相容別名與薄轉發層。<br>3. **孤兒死代碼 (Dead Code)**：經全空間調用圖譜查驗無任何生產或測試調用之廢棄函式、分支與未引用變數（在 `Mode B` 下經嚴格查驗 0 外部調用之純內部死代碼亦屬此列）。 | `S2`, `S6` |
| **`D3`** | **控制流與認知複雜度**<br>*(Control Flow & Cognitive Complexity)* | • 圈複雜度与認知複雜度<br>• 縮排深度上限 ($\le 3$ 層)<br>• 結構性重複收斂 (DRY) | 1. **箭頭型深層巢狀 (Arrow Anti-pattern)**：`if / for / try` 連續縮排超過 3~4 層，核心主邏輯被擠在最內層。<br>2. **超長程序 (Long Procedure)**：單一函式超過 60~80 行，包含多個隱含階段且透過大量局部可變變數交織狀態。<br>3. **同構樣板散落**：多個業務方法重複編寫相同的「前置檢查 $\to$ 資源獲取 $\to$ 錯誤轉換 $\to$ 清理」骨架。 | `S1`, `S3`, `S4` |
| **`D4`** | **介面契約與資源生命週期**<br>*(Contracts & Resource Lifecycle)* | • 靜態型別簽名完整性<br>• 異常傳播透明性<br>• 確定性資源釋放 (RAII / Scoped) | 1. **鬆散容器與長參數列**：函式超過 5~6 個散裝參數，或以無型別約束之裸字典 (`dict` / `Map` / `any`) 跨多階段讀寫業務狀態。<br>2. **異常掩蓋**：空白或過寬的例外捕捉塊吞掉底層錯誤，或將錯誤碼與異常混用。<br>3. **資源洩漏風險**：檔案控制代碼、網路連線、暫存目錄或互斥鎖未置於 `with` / `using` / `defer` / `try...finally` 保護中。 | `S3`, `S5` |
| **`D5`** | **架構邊界與專案慣例**<br>*(Architectural Idioms)* | • 基礎設施抽象層遵從度<br>• 常數與組態集中化<br>• 依賴層級隔離紀律 | 1. **繞過宿主基礎設施**：未遵循專案統一的虛擬路徑/檔案代理層、日誌或組態介面，直接硬編碼相對路徑或散落原生系統呼叫。<br>2. **魔術常數散落**：業務邏輯中硬編碼超時秒數、重試上限、緩衝區大小或狀態字面量。<br>3. **跨層反向耦合**：底層核心模組反向依賴上層選配業務模組，或違反核心模組零第三方依賴約束（含注入於 `CODE_OPTIMIZER_STANDARDS` 之專案特化規則）。 | `S5`, `S6` |

## 3. R01 調研診斷報告 (`R01_code_optimization_audit.md`) 結構指引

在步驟 2 完成探索與 `D1~D5` 診斷後，讀取標準調研模板 [`RXX_research_report.md`](`__#{module://agents-workflow/assets/templates/RXX_research_report.md}__`)，於計畫目錄產出 `R01_code_optimization_audit.md`，內文須包含以下結構化章節：

1. **定錨基準與範圍摘要**：
   - 記錄開發者於步驟 1 拍板之 **「檢視範圍（全專案 / 單一模組 / 單一檔案）」** 與 **「生命週期模式（`Mode A` 收斂期 vs. `Mode B` 維護期）」**，以及現行測試基線狀態。
2. **契約邊界與內部工具函式查驗表**：
   - 明確列出「公開契約入口清單（`Mode A` 預計收斂為單一入口並同步改寫之調用點 / `Mode B` 預計保留門面重匯出之符號）」與 **「經嚴格查驗確認 0 外部跨模組調用之純內部工具函式清單（`Mode A` 與 `Mode B` 均直接執行破壞性收斂）」**。
3. **`D1 ~ D5` 五維度分級診斷矩陣**：
   - 逐一列出 `D1`~`D5` 檢查結果（包含 `檔案路徑:行號區間`、`P0/P1/P2` 等級、具體病徵描述；無異常維度標記 `Pass`）。
4. **`S1 ~ S6` 外科手術重構處方箋（Refactoring Blueprint）**：
   - 具體說明預計提取哪些內部階段函式（`S1`）、將哪些方法剝離為無狀態純函式（`S2`）、如何拉平控制流或封裝資料團塊（`S3~S5`）、以及是否需執行物理拆檔（`S6`）與拆檔後的模組拓撲。
5. **風險評估與推薦流轉出口**：
   - 依據變更規模，明確給出選擇「出口 ① 立即實作」時應轉入之計畫軌道建議（`Fast Track` / `Full Track` / `Umbrella`）。
