# 既有測試集六維度體檢與純化重構指南 (Test Suite Audit & Purification)

本參考指南定義對既有 `tests/` 目錄執行六維度體檢、消除歷史退化病灶、整併碎片測試檔與子系統 1:1 歸戶收斂的標準作業流程。

---

## 1. 六大測試病灶體檢模型 (The Six Test Smells)

| 病灶編號 | 病灶名稱 | 判定特徵與典型反模式 | 處置與純化原則 |
| :---: | :--- | :--- | :--- |
| **`T-01`** | **虛假空殼與寬容放行斷言**<br/>*(Vacuous & Lenient Assertions)* | 1. 待測目標自身被 Mock<br/>2. 僅斷言 `assertIsNotNone(res)` 或 `assertIn(rc, (0, 1))` 充數<br/>3. 以 `if found:` 包覆關鍵斷言，找不到檔案時靜默過關 | 重寫斷言，強制檢查真實副作用（回傳值、寫入內容或狀態遷移）；補齊負向非法輸入攔截斷言。 |
| **`T-02`** | **計畫名碎片檔與跨檔重複初始化**<br/>*(Fragmentation & Redundant Setup)* | 1. 存在以單次開發計畫、修復任務或日期命名之測試檔（如 `test_build_git_decoupling.py`）<br/>2. 同一元件之不同方法散落於多檔重複建立沙盒與測試資料 | 將案例依被測子系統 1:1 歸入 `test_<subsystem>.*`；刪除碎片檔並統一套用子系統 Fixture / Setup。 |
| **`T-03`** | **歷史墓碑與死代碼殘留**<br/>*(Tombstones & Obsolete Tests)* | 1. 重構刪除舊方法後，殘留 `assertFalse(hasattr(cls, 'old_api'))`<br/>2. 持續測試已無呼叫者的棄用函式或內部死代碼 | 徹底刪除墓碑測試與死代碼測試檔，維持測試集與現行生產代碼 1:1 精確映射。 |
| **`T-04`** | **跨層反向耦合與非必要靜態搜尋**<br/>*(Cross-Layer Coupling & Doc Grep)* | 1. 底層模組單元測試反向依賴或 `patch` 上層選配業務模組<br/>2. 在單元測試中 grep 外部靜態 Markdown 代替調用真實管線執行產出 | 解耦反向依賴，使底層單元測試可獨立全綠；將靜態 grep 改為呼叫真實生成與驗證函式。 |
| **`T-05`** | **真實工作區狀態污染與漏清理**<br/>*(Workspace State Pollution)* | 1. 測試直接寫入專案 `config/` 或工作目錄<br/>2. 未使用隔離沙盒，或中途斷言失敗導致 `tearDown` 漏清理暫存目錄 | 強制使用隔離沙盒基底類別或暫存目錄；所有清理邏輯包覆於 `tearDown` 或 `try...finally`。 |
| **`T-06`** | **高風險負向邊界與核心契約漏測**<br/>*(Missing Negative Coverage)* | 1. 僅包含正向 Happy Path，無非法傳參、檔案損毀、權限不足或超時測試<br/>2. 核心公開 API 缺少例外拋出與錯誤碼斷言 | 針對核心公開 API 補齊邊界測試（`ET-XX`）與負向錯誤攔截案例。 |

---

## 2. 存量測試集三步純化收斂工作流 (3-Step Purification Workflow)

執行存量測試集體檢與純化時，強制遵循以下三步作業程序：

```text
Step 1: 六維度盤點與病灶標記
  ├── 走訪目標 tests/ 目錄下所有檔案
  └── 逐檔比對 T-01 ~ T-06 六大病灶，統計碎片檔案數量與重複案例

Step 2: 產出「測試集體檢與子系統 1:1 歸戶映射表」等待確認 Gate (強制 End Turn)
  ├── 呈遞體檢報告矩陣：現有測試檔 -> 目標子系統歸戶檔案 -> 涉及病灶
  └── 明確呈報預計整併之檔案清單與刪除之碎片檔，經開發者確認同意後再動筆

Step 3: 無損整併、碎片檔清理與實機全綠回歸驗證
  ├── 將測試案例遷移至目標 test_<subsystem>.* 既有檔案，清理重複 Mock 與重複 Setup
  ├── 徹底刪除被整併之碎片測試檔 (git rm)
  └── 實機執行全系統回歸測試，確認 100% Passed 且 git status 零殘留
```
