# 深度歸因與防淺層修復工作流 (Discuss)

本工作流為開發過程（特別是 Phase 5 實作與 Phase 6 測試）遇非預期錯誤、測試失敗或範疇越界時的**強制停手與深度歸因機制**，杜絕盲目試錯與淺層修補。執行規範遵循 [NewPlan](`__#{module://agents-workflow/assets/workflows/NewPlan.md}__`)。

---

## 🎯 觸發條件

發生以下任一情況時，**必須立即停止修改任何程式碼**，主動發起本流程：
1. **範疇越界**：排查時發現需修改非當前計畫承諾範圍之檔案或模組。
2. **連續修復失敗**：針對同一報錯或測試缺陷，連續 2 次修復嘗試未通過。
3. **破壞性變更**：修復方案將破壞 Public API 契約、既有架構或引入非預期跨模組依賴。
4. **開發者調用**：開發者下達 `/Discuss` 指令。

---

## 🛡️ 排查優先級：由近及遠、本體優先

排查時強制遵循以下階層，嚴禁越級懷疑：

```text
優先級 1：當前本體組件 (組件內部狀態、計算邏輯與邊界防護)
   ⬇ (確認本體正確後)
優先級 2：呼叫端傳參與時序 (傳遞給外部之參數、格式、單位與生命週期時序)
   ⬇ (確認傳參與時序正確後，方可懷疑外部)
優先級 3：下游/外部組件 (外部模組確有缺陷) ➔ 觸發本討論向開發者報告！
```

---

## 🚀 執行步驟

### 步驟 1：現場呈遞與 5-Whys 根因歸因
1. **現場證據**：客觀記錄報錯摘要、發生檔案位置與傳參呼叫現場。
2. **5-Whys 根因**：分析架構、時序或資料狀態為何流入該錯誤分支，追溯本質根因而非表面現象。

### 步驟 2：呈遞修復方案矩陣與討論卡
呈遞 2~3 種具體修復方案（分析各自影響範圍與 Trade-offs）。
對話 Session **嚴禁代碼傾倒、日誌全文傾倒或冗長論述**，強制僅呈遞以下極簡討論卡，並**立即 End Turn 等待開發者決策**：

```markdown
### 🛑 /Discuss 深度歸因與討論卡
- **觸發原因**：[範疇越界 / 連續 2 次修復失敗 / 破壞性變更 / 開發者調用]
- **異常現場**：[錯誤訊息摘要 / 發生檔案位置]
- **5-Whys 根因**：[1~2 行客觀架構/時序根因分析]
- **修復候選方案**：
  1. **方案 A (推薦)**：[方案簡述]（影響範疇：[小/中/大]，Trade-off：[簡述]）
  2. **方案 B**：[方案簡述]（影響範疇：[小/中/大]，Trade-off：[簡述]）
- **待確認事項**：請確認採取方案 A、方案 B 或有其他指引？
```

### 步驟 3：決策固化與恢復執行
獲得開發者指示後：
1. **決策記錄**：於當前計畫之 [`changelog.md`](`__#{module://agents-workflow/assets/templates/changelog.md}__`) 或對應 Phase 文件登載標準 `[{Phase}:DR-XX]` 決策記錄。
2. **產物回填**：若影響架構或任務，回填更新 [`P02_architecture_plan.md`](`__#{module://agents-workflow/assets/templates/P02_architecture_plan.md}__`)、[`P04_implementation_plan.md`](`__#{module://agents-workflow/assets/templates/P04_implementation_plan.md}__`) 或 [`P05_task.md`](`__#{module://agents-workflow/assets/templates/P05_task.md}__`)。
3. **恢復執行**：依共識方案恢復實作或測試推進。
